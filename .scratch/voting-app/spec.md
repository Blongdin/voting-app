# 투표 앱 v1

Status: ready-for-agent

용어는 루트의 `CONTEXT.md`를 따르고, 설계 근거는 ADR-0001~0004(`docs/adr/`)에 있다.

## Problem Statement

질문 하나를 올려 사람들의 의견을 빠르게 모으고 싶지만, 기존 설문 도구는 가입, 설정, 긴 양식이 필요해 번거롭다. 참여자는 링크를 열자마자 선택지 하나를 누르고 결과를 보고 싶어 하고, 운영자는 투표를 만들고 닫고 지우는 일을 복잡한 관리 도구 없이 하고 싶어 한다.

## Solution

누구나 로그인 없이 투표 목록을 보고, 투표에 들어가 선택지 하나에 표를 내고, 결과를 볼 수 있는 웹앱을 만든다. 한 브라우저는 투표마다 한 표만 낼 수 있고, 결과는 표를 낸 뒤에만 공개된다. 운영자는 비밀번호 하나로 로그인해 투표를 만들고, 마감하고, 삭제한다. 앱은 Vercel에 배포하고 데이터는 Neon Postgres에 저장한다.

## User Stories

### 투표 목록

1. 참여자로서, 홈에서 투표 목록을 보고 싶다. 그래야 참여할 투표를 고를 수 있다.
2. 참여자로서, 진행 중인 투표가 마감된 투표보다 위에 나오면 좋겠다. 그래야 지금 참여할 수 있는 투표를 먼저 찾을 수 있다.
3. 참여자로서, 각 그룹 안에서 최신 투표가 먼저 나오면 좋겠다. 그래야 새 투표를 놓치지 않는다.
4. 참여자로서, 목록에서 투표마다 질문, 상태(진행 중/마감), 총 표 수를 보고 싶다. 그래야 들어가기 전에 어떤 투표인지 알 수 있다.
5. 참여자로서, 투표가 하나도 없을 때 "아직 투표가 없습니다" 같은 안내를 보고 싶다. 그래야 화면이 고장 난 것이 아님을 안다.

### 표 내기

6. 참여자로서, 투표마다 고유한 링크가 있으면 좋겠다. 그래야 다른 사람에게 특정 투표를 공유할 수 있다.
7. 참여자로서, 투표 화면에서 질문과 모든 선택지를 보고 싶다. 그래야 무엇을 고를지 판단할 수 있다.
8. 참여자로서, 로그인 없이 선택지 하나를 골라 표를 내고 싶다. 그래야 가입 없이 빠르게 참여할 수 있다.
9. 참여자로서, 선택지를 고르지 않으면 표를 낼 수 없으면 좋겠다. 그래야 실수로 빈 표를 내지 않는다.
10. 참여자로서, 표를 내면 곧바로 결과 화면으로 넘어가고 싶다. 그래야 다른 사람들의 선택을 확인할 수 있다.
11. 참여자로서, 이미 표를 낸 투표에 다시 들어가면 투표 양식 대신 결과가 보이면 좋겠다. 그래야 내가 이미 참여했음을 안다.
12. 참여자로서, 이미 표를 낸 투표에 다시 표를 내려 하면 "이미 참여한 투표입니다"라는 안내와 함께 결과를 보고 싶다. 그래야 무슨 일이 일어났는지 이해할 수 있다.
13. 참여자로서, 투표 양식을 보는 사이에 투표가 마감되어 표가 거절되면 "마감된 투표입니다"라는 안내와 함께 결과를 보고 싶다. 그래야 표가 반영되지 않은 이유를 안다.
14. 참여자로서, 낸 표는 바꿀 수 없다는 것을 표를 내기 전에 알고 싶다. 그래야 신중하게 고른다.
15. 참여자로서, 한동안 앱을 쓰지 않았다가 돌아와도 내가 참여한 투표가 기억되면 좋겠다. 그래서 참여자 쿠키는 1년간 유지된다.

### 결과 보기

16. 참여자로서, 결과에서 선택지마다 표 수, 비율(%), 막대를 보고 싶다. 그래야 분포를 한눈에 파악할 수 있다.
17. 참여자로서, 총 표 수를 보고 싶다. 그래야 결과가 얼마나 많은 사람을 대표하는지 안다.
18. 참여자로서, 내가 고른 선택지가 표시되면 좋겠다. 그래야 내 선택을 다른 사람들과 비교할 수 있다.
19. 참여자로서, 진행 중인 투표의 결과는 페이지를 새로고침하지 않아도 몇 초마다 갱신되면 좋겠다. 그래야 투표 흐름을 지켜볼 수 있다.
20. 참여자로서, 표를 내기 전에는 결과를 볼 수 없으면 좋겠다. 그래야 다른 사람들의 선택에 휩쓸리지 않고 고를 수 있다.
21. 참여자로서, 결과 조회 주소를 직접 호출해도 표를 내기 전에는 결과를 받을 수 없으면 좋겠다. 그래야 결과 공개 규칙을 우회할 수 없다.
22. 참여자로서, 마감된 투표의 결과는 표를 내지 않았어도 볼 수 있으면 좋겠다. 그래야 끝난 투표의 결론을 확인할 수 있다.
23. 참여자로서, 마감된 투표에서는 투표 양식이 보이지 않고 "마감됨" 표시와 결과만 보이면 좋겠다. 그래야 더는 참여할 수 없음을 안다.
24. 참여자로서, 삭제되었거나 존재하지 않는 투표의 링크를 열면 "찾을 수 없는 투표" 404 페이지를 보고 싶다. 그래야 링크가 더는 유효하지 않음을 안다.

### 운영자 로그인

25. 운영자로서, 비밀번호로 운영자 화면에 로그인하고 싶다. 그래야 나만 투표를 관리할 수 있다.
26. 운영자로서, 비밀번호가 틀리면 "비밀번호가 올바르지 않습니다"라는 안내를 보고 싶다. 그래야 다시 시도할 수 있다.
27. 운영자로서, 로그인이 하루 동안 유지되면 좋겠다. 그래야 작업 중에 계속 다시 로그인하지 않아도 된다.
28. 운영자로서, 하루가 지나면 자동으로 로그아웃되면 좋겠다. 그래야 공용 기기에 세션이 오래 남지 않는다.
29. 운영자로서, 로그아웃 버튼을 누르면 곧바로 로그아웃되면 좋겠다. 그래야 다른 사람이 내 세션을 쓰지 못한다.
30. 운영자로서, 로그인하지 않은 상태로 운영자 화면에 들어가면 로그인 화면이 나오면 좋겠다. 그래야 관리 기능이 노출되지 않는다.
31. 운영자로서, 로그인하지 않은 사람이 만들기, 마감, 삭제 요청을 직접 보내도 거절되면 좋겠다. 그래야 화면을 거치지 않는 공격을 막을 수 있다.

### 운영자의 투표 관리

32. 운영자로서, 운영자 화면에서 모든 투표를 상태와 총 표 수와 함께 보고 싶다. 그래야 무엇을 관리해야 하는지 알 수 있다.
33. 운영자로서, 질문과 선택지를 입력해 새 투표를 만들고 싶다. 그래야 의견을 모을 수 있다.
34. 운영자로서, 선택지 입력 칸을 2개에서 10개 사이로 늘리거나 줄이고 싶다. 그래야 질문에 맞는 개수를 쓸 수 있다.
35. 운영자로서, 질문이 비었거나 200자를 넘으면 투표가 만들어지지 않고 이유를 보고 싶다. 그래야 고쳐서 다시 제출할 수 있다.
36. 운영자로서, 선택지가 2개보다 적거나 10개보다 많거나, 빈 선택지나 100자를 넘는 선택지가 있으면 투표가 만들어지지 않고 이유를 보고 싶다. 그래야 잘못된 투표가 만들어지지 않는다.
37. 운영자로서, 같은 선택지를 두 번 넣으면 거절되면 좋겠다. 그래야 표가 두 선택지로 나뉘지 않는다.
38. 운영자로서, 입력의 앞뒤 공백이 자동으로 지워지면 좋겠다. 그래야 공백 때문에 생기는 중복이나 빈 입력을 걱정하지 않아도 된다.
39. 운영자로서, 투표를 만든 직후 그 투표의 링크를 확인하고 싶다. 그래야 바로 공유할 수 있다.
40. 운영자로서, 진행 중인 투표를 마감하고 싶다. 그래야 더는 표를 받지 않고 결과를 확정할 수 있다.
41. 운영자로서, 마감은 되돌릴 수 없다는 것을 마감하기 전에 알고 싶다. 그래야 실수로 마감하지 않는다.
42. 운영자로서, 투표를 삭제하고 싶다. 그래야 잘못 만든 투표나 필요 없는 투표를 없앨 수 있다.
43. 운영자로서, 삭제하기 전에 "이 투표와 표 N개가 삭제됩니다"라는 확인 창을 보고 싶다. 그래야 되돌릴 수 없는 삭제를 실수로 하지 않는다.
44. 운영자로서, 삭제하면 선택지와 표까지 함께 완전히 지워지면 좋겠다. 그래야 남은 데이터를 따로 정리하지 않아도 된다.
45. 운영자로서, 표를 내지 않아도 진행 중인 투표의 결과를 언제든 보고 싶다. 그래야 진행 상황을 파악할 수 있다.
46. 운영자로서, 운영자 화면에서 결과를 볼 때도 진행 중인 투표는 몇 초마다 갱신되면 좋겠다. 그래야 실시간으로 지켜볼 수 있다.

### 개발과 배포

47. 개발자로서, 명령 하나로 DB 스키마를 적용하고 싶다. 그래야 새 환경을 쉽게 준비할 수 있다.
48. 개발자로서, 스키마 적용을 여러 번 실행해도 안전하면 좋겠다. 그래야 이미 적용된 환경에서 실수로 실행해도 문제가 없다.
49. 개발자로서, 운영, 개발, 테스트 DB가 분리되어 있으면 좋겠다. 그래야 테스트가 운영 데이터를 건드리지 않는다.
50. 개발자로서, 환경변수 세 개(DB 연결, 운영자 비밀번호, 세션 서명 키)만 설정하면 앱이 동작하면 좋겠다. 그래야 Vercel 배포가 간단하다.

## Implementation Decisions

### 모듈

- **투표 도메인 모듈**은 투표, 선택지, 표, 결과에 관한 모든 규칙을 가진다. 앱 전체에서 규칙이 있는 곳은 여기뿐이다. 인터페이스는 다음과 같다.
  - **투표 목록 조회**: 목록 정렬 규칙(진행 중 먼저, 각 그룹 안에서 최신순)과 항목별 총 표 수를 포함한다.
  - **투표 하나 조회**: 없는 투표면 "없음"을 돌려준다.
  - **투표 만들기(행위자, 질문, 선택지 목록)**: 입력을 정리하고(앞뒤 공백 제거) 검증한다. 검증에 실패하면 어느 항목이 왜 틀렸는지 담긴 결과를 돌려준다.
  - **투표 마감(행위자, 투표 ID)**, **투표 삭제(행위자, 투표 ID)**: 행위자가 운영자가 아니면 거절한다. 이미 마감된 투표를 다시 마감하는 요청은 아무것도 바꾸지 않는다.
  - **표 내기(투표 ID, 선택지 ID, 참여자 ID)**: 결과는 성공, 이미 표를 냄, 마감됨, 잘못된 선택지, 없는 투표 중 하나다.
  - **결과 조회(투표 ID, 보는 사람)**: 보는 사람이 표를 냈거나, 투표가 마감됐거나, 보는 사람이 운영자일 때만 결과를 돌려준다. 그 밖에는 "권한 없음"이고, 없는 투표면 "없음"이다.
  - "행위자"와 "보는 사람"은 {운영자인지, 참여자 ID(없을 수 있음)}로 이루어진 같은 모양이다. 이 모듈은 쿠키나 HTTP를 알지 못한다.
- **운영자 인증 모듈**은 DB를 쓰지 않는 순수 모듈이다(ADR-0002).
  - **로그인(비밀번호)**: 환경변수의 운영자 비밀번호와 상수 시간 비교를 한다. 맞으면 서명된 세션 토큰을, 틀리면 실패를 돌려준다.
  - **세션 검증(토큰, 현재 시각)**: 서명과 발급 후 1일 만료를 확인한다. 서명 키는 환경변수에서 읽는다.
- **연결 코드**: Server Actions(로그인, 로그아웃, 투표 만들기, 마감, 삭제, 표 내기)와 결과 조회 Route Handler 하나를 둔다. 이들은 쿠키에서 운영자 세션과 참여자 ID를 읽어 "행위자"와 "보는 사람"을 만들고, 도메인 모듈을 호출한 뒤 결과를 화면용으로 바꾸기만 한다. 규칙을 판단하는 코드를 두지 않는다.
- 운영자 권한은 `proxy`에만 맡기지 않는다. Server Action과 운영자 페이지 각각에서 세션을 검증하는 공통 헬퍼로 확인한다(ADR-0002).

### 참여자 식별

- 참여자 ID는 첫 표를 낼 때 무작위 UUID로 만들어 HttpOnly, Secure, SameSite=Lax 쿠키로 발급한다. 유효기간은 1년이다(ADR-0001).
- 쿠키가 없는 방문자는 참여자 ID가 없는 보는 사람으로 취급한다. 이 사람은 마감된 투표의 결과만 볼 수 있다.

### 데이터 모델

모든 규칙은 가능한 한 DB 제약으로 보장한다(ADR-0004). 스키마는 여러 번 실행해도 안전한 SQL 파일 하나로 관리하고 스크립트 명령으로 적용한다. ORM은 쓰지 않는다(ADR-0003).

- **투표(polls)**
  - ID: UUID, DB가 생성
  - 질문: 1~200자
  - 만든 시각
  - 마감 시각: 없으면 진행 중
- **선택지(options)**
  - ID: UUID
  - 소속 투표 ID: 투표 삭제 시 함께 삭제
  - 문구: 1~100자
  - 표시 순서: 0부터
  - (소속 투표, 문구) 조합과 (소속 투표, 표시 순서) 조합이 각각 유일하다.
- **표(votes)**
  - ID
  - 소속 투표 ID: 투표 삭제 시 함께 삭제
  - 선택지 ID
  - 참여자 ID
  - 낸 시각
  - (소속 투표, 참여자 ID) 조합이 유일하다. 이것으로 한 사람당 한 표를 보장한다.
  - (선택지 ID, 소속 투표 ID)가 선택지의 (ID, 소속 투표)를 참조하는 복합 외래키를 둔다. 이것으로 다른 투표의 선택지에 표를 낼 수 없게 한다.
- 마감 여부는 표를 넣는 같은 SQL 문 안에서 확인한다. 조회한 뒤 따로 넣는 방식은 쓰지 않는다.
- 선택지 개수(2~10개) 제한은 도메인 모듈의 입력 검증에서 한다. 투표와 선택지는 한 트랜잭션 안에서 함께 만든다.

### 결과 API 계약

- 결과 조회 Route Handler는 투표 ID 하나를 받아 도메인 모듈의 결과 조회를 그대로 따른다.
  - 권한 없음: 403
  - 없는 투표: 404
  - 성공: 200
- 성공 응답에는 다음이 들어간다.
  - 투표 상태(진행 중/마감)
  - 총 표 수
  - 선택지별 {ID, 문구, 표 수, 비율}: 표시 순서대로. 비율은 정수로 반올림하고, 총 표 수가 0이면 모두 0이다.
  - 보는 사람이 고른 선택지 ID: 없을 수 있음
- 응답은 캐시하지 않는다.

### 화면과 상호작용

- 경로
  - 홈: 투표 목록
  - 투표 화면: 투표마다 고유 경로
  - 운영자 화면: 로그인, 목록, 만들기
- 투표 화면은 보는 사람에 따라 다르게 보인다.
  - 진행 중이고 아직 표를 내지 않은 참여자: 투표 양식
  - 그 밖: 결과
- 표 내기 결과가 "이미 표를 냄"이나 "마감됨"이면 해당 안내 문구와 함께 결과 화면을 보여 준다. "잘못된 선택지"는 일반 오류 안내로 보여 준다.
- 없는 투표 경로는 404 페이지를 보여 준다.
- 결과 화면은 진행 중인 투표에서 5초마다 결과 API를 다시 호출한다. 탭이 숨겨져 있으면 멈췄다가 다시 보이면 이어서 하고, 응답에서 투표가 마감됐다고 나오면 멈춘다.
- 운영자 화면에는 로그아웃 버튼이 있다. 누르면 세션 쿠키를 지우고 로그인 화면으로 보낸다.
- 마감과 삭제는 브라우저 확인 창을 거친다. 삭제 확인 문구에는 해당 투표의 총 표 수가 들어간다.
- 화면 문구는 한국어만 쓴다. 스타일은 Tailwind로 한다.

### 환경

- Neon 브랜치는 세 개다.
  - 운영: Vercel 환경변수에 연결
  - 개발: 로컬 환경변수 파일에 연결
  - 테스트: 테스트 실행 시 연결
- 필요한 환경변수는 DB 연결 문자열, 운영자 비밀번호, 세션 서명 키 세 개다.

## Testing Decisions

- 좋은 테스트는 모듈의 공개 인터페이스로 관찰할 수 있는 동작만 검증한다. SQL 문장, 테이블 내부 구조, 토큰 형식 같은 구현 세부 사항은 검증하지 않는다. 테스트 이름은 `CONTEXT.md`의 용어(투표, 선택지, 표, 마감, 참여자, 운영자)를 쓴다.
- 테스트 경계는 두 개다.
  - **투표 도메인 모듈**: Neon 테스트 브랜치의 실제 Postgres로 테스트한다. 규칙을 DB 제약으로 보장하기 때문에 mock으로는 검증할 수 없다(ADR-0004). 테스트마다 테이블을 비운다.
  - **운영자 인증 모듈**: DB 없이 테스트한다. 현재 시각을 인자로 넣어 만료를 검증한다.
- 연결 코드(Server Actions, Route Handler, 쿠키 처리)와 UI는 자동 테스트하지 않고 직접 실행해서 확인한다.
- 테스트 도구는 Vitest다. 저장소에 기존 테스트가 없어서 참고할 선례는 없고, 이 스펙의 테스트가 첫 선례가 된다.
- 테스트할 동작
  - 투표 만들기: 올바른 입력은 성공한다.
  - 투표 만들기 입력 검증: 빈 질문, 200자 초과 질문, 선택지 1개, 선택지 11개, 빈 선택지, 100자 초과 선택지, 중복 선택지(공백 제거 후 비교 포함)는 각각 거절된다.
  - 운영자 권한: 운영자가 아닌 행위자의 만들기, 마감, 삭제는 거절된다.
  - 표 내기: 성공하면 결과에 반영된다.
  - 중복 표: 같은 참여자가 같은 투표에 두 번째 표를 내면 "이미 표를 냄"이 되고, 결과의 표 수는 변하지 않는다.
  - 동시 중복 표: 같은 참여자의 표 두 개를 동시에 보내도 하나만 들어간다.
  - 마감된 투표에 표를 내면 "마감됨"이 된다.
  - 다른 투표의 선택지로 표를 내면 "잘못된 선택지"가 된다.
  - 없는 투표에 표를 내거나 결과를 조회하면 "없는 투표"가 된다.
  - 결과 공개 규칙
    - 표를 내지 않은 참여자와 참여자 ID가 없는 사람은 진행 중인 투표의 결과를 받을 수 없다.
    - 표를 낸 참여자는 결과를 받는다.
    - 운영자는 언제든 결과를 받는다.
    - 누구나 마감된 투표의 결과를 받는다.
  - 결과 내용: 선택지별 표 수, 비율(0표일 때 0 포함), 총 표 수, 보는 사람이 고른 선택지가 맞다.
  - 삭제: 삭제한 투표는 목록과 조회에서 사라지고, 결과 조회가 "없는 투표"가 된다.
  - 목록 정렬: 진행 중인 투표가 먼저 나오고, 각 그룹 안에서 최신순이다.
  - 로그인: 맞는 비밀번호는 세션을 발급하고, 틀린 비밀번호는 실패한다.
  - 세션 검증: 발급 직후에는 유효하다. 1일이 지나면 무효가 되고, 변조된 토큰과 다른 서명 키로 만든 토큰도 무효다.

## Acceptance Criteria

- [ ] 홈에 투표 목록이 진행 중 먼저, 각 그룹 안에서 최신순으로 나오고, 항목마다 질문, 상태, 총 표 수가 보인다.
- [ ] 투표가 없으면 안내 문구가 보인다.
- [ ] 투표마다 고유 링크가 있고, 없는 투표의 링크는 404 페이지를 보여 준다.
- [ ] 참여자가 로그인 없이 선택지 하나를 골라 표를 내면 결과 화면으로 넘어간다.
- [ ] 한 브라우저는 투표마다 한 표만 낼 수 있고, 낸 표는 바꿀 수 없다.
- [ ] 이미 표를 낸 투표에 다시 들어가면 결과가 보인다.
- [ ] 이미 표를 냈거나 마감된 투표에 표를 내려 하면 해당 안내와 함께 결과가 보인다.
- [ ] 참여자 쿠키는 1년간 유지된다.
- [ ] 표를 내지 않은 참여자는 진행 중인 투표의 결과를 화면으로도, 결과 API를 직접 호출해서도 볼 수 없다(API는 403).
- [ ] 마감된 투표의 결과는 누구나 볼 수 있고, 마감된 투표에는 투표 양식이 없다.
- [ ] 결과에 선택지별 표 수, 비율, 막대, 총 표 수, 내가 고른 선택지 표시가 나온다.
- [ ] 진행 중인 투표의 결과는 5초마다 갱신되고, 탭이 숨겨지면 멈췄다가 다시 보이면 이어서 하며, 마감되면 멈춘다.
- [ ] 운영자는 비밀번호로 로그인하고, 세션은 1일 뒤 만료되며, 로그아웃 버튼으로 곧바로 로그아웃할 수 있다.
- [ ] 틀린 비밀번호에는 안내 문구가 보인다.
- [ ] 로그인하지 않은 사람은 운영자 화면에 들어갈 수 없고, 만들기, 마감, 삭제 요청을 직접 보내도 거절된다.
- [ ] 운영자는 질문(200자 이하)과 선택지(2~10개, 각 100자 이하, 중복 없음)로 투표를 만들 수 있다. 앞뒤 공백은 지워지고, 잘못된 입력은 이유와 함께 거절된다.
- [ ] 운영자는 확인 창을 거쳐 투표를 마감할 수 있고, 마감은 되돌릴 수 없다.
- [ ] 운영자는 "이 투표와 표 N개가 삭제됩니다" 확인 창을 거쳐 투표를 삭제할 수 있고, 선택지와 표도 함께 지워진다.
- [ ] 운영자는 표를 내지 않아도 모든 투표의 결과를 볼 수 있다.
- [ ] 스키마 적용 명령은 여러 번 실행해도 안전하다.
- [ ] Testing Decisions의 테스트가 모두 Neon 테스트 브랜치에서 통과한다.
- [ ] 환경변수 세 개로 Vercel에 배포되어 운영 브랜치에서 동작한다.
- [ ] 모든 화면 문구가 한국어다.

## Out of Scope

- 투표 수정, 표 변경, 마감 되돌리기, 삭제된 투표 복구
- 만들 때 정하는 자동 마감 시각
- 운영자 개별 계정, 작업 기록, 로그인 시도 제한
- 참여자 로그인, IP 기반 중복 차단, 봇이나 악의적 중복 투표 방어(시크릿 창으로 다시 투표하는 것은 허용되는 한계)
- 여러 개를 고르는 투표, 순위 투표, 참여자가 선택지를 추가하는 기능
- WebSocket 같은 실시간 연결(5초 폴링으로 대신함)
- 다국어 지원, 목록 페이지 나누기, 검색
- 결과 내보내기(CSV 등)
