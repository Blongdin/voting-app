# 07: 운영자의 투표 삭제

**What to build:** 운영자가 "이 투표와 표 N개가 삭제됩니다" 확인 창을 거쳐 투표를 삭제한다. 투표의 선택지와 표까지 함께 완전히 지워지고, 복구 기능은 없다. 삭제한 투표는 목록에서 사라지고, 그 링크는 404 페이지를 보여 준다.

**Blocked by:** 03 (운영자가 투표를 만들고, 참여자가 목록과 투표 화면에서 확인)

**Status:** done

- [x] 도메인 모듈에 **투표 삭제(행위자, 투표 ID)**가 있다.
  - 운영자가 아닌 행위자의 요청은 거절된다.
  - 선택지와 표는 DB의 연쇄 삭제로 함께 지워진다.
- [x] 테스트가 통과한다.
  - 삭제한 투표는 목록과 조회에서 사라진다. 조회 결과는 "없음"이다.
  - 04가 완료된 뒤라면, 삭제한 투표의 결과 조회도 "없는 투표"다.
  - 운영자가 아닌 행위자의 삭제는 거절된다.
- [x] 운영자 화면에서 삭제 버튼을 누르면 해당 투표의 총 표 수가 들어간 "이 투표와 표 N개가 삭제됩니다" 확인 창이 뜬다.
- [x] 삭제한 투표는 홈 목록과 운영자 목록에서 사라진다.
- [x] 삭제한 투표의 링크로 들어가면 404 페이지가 보인다.

## Comments

- 2026-09-30: 완료. 커밋 4c19587(구현)과 리뷰 반영 커밋. 테스트 50개가 통과했다(삭제 4개, 연쇄 삭제 포함).
- 헤드리스 Chrome으로 확인한 것:
  - 확인 창 문구는 "이 투표와 표 N개가 삭제됩니다"이고, N은 화면의 실시간 표 수를 따른다(1 → 3).
  - 취소하면 투표가 남는다.
  - 확인하면 /admin으로 돌아가고, 투표·선택지·표 행이 모두 사라진다.
  - 삭제한 투표는 목록에서 빠지고, 링크는 404가 된다.
  - 쿠키 없이 재전송하면 로그인 화면으로 가고, 삭제되지 않는다.
- 결정: 마감과 삭제 버튼은 운영자 결과 화면에 둔다(06과 같다).
- 리뷰 반영:
  - 삭제 확인 창의 표 수가 오래된 값으로 남던 문제를 고쳤다. `useLivePollResults` 훅으로 결과와 버튼이 같은 상태를 쓴다.
  - 연쇄 삭제 테스트를 추가했다.
  - 마감과 삭제의 결과 타입을 `AdminPollChangeResult`로 합쳤다.
