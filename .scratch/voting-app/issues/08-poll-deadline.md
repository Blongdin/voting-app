# 08: 마감 시각을 정해 두면 투표가 스스로 마감된다

**What to build:** 운영자가 투표를 만들 때 마감 시각을 정할 수 있다. 마감 시각을 넣지 않아도 된다. 마감 시각이 지나면 그 투표는 운영자가 따로 닫지 않아도 마감이다. 마감되면 표를 받지 않고, 누구나 결과를 보며, 목록에서는 마감 쪽으로 간다. 마감 시각 전이라도 운영자는 "마감하기"로 일찍 끝낼 수 있다. 마감 시각은 만든 뒤 바꿀 수 없다. 판단 방식은 ADR-0005를 따른다.

**Blocked by:** 03, 04, 06 (모두 완료)

**Status:** done

- [x] 스키마에 `polls.closes_at`(비어 있을 수 있음)과 DB 함수 `is_closed(closed_at, closes_at)`가 추가된다. 기존 DB에 여러 번 적용해도 안전하다.
- [x] 목록, 조회, 결과, 표 내기, 결과 공개 규칙이 모두 `is_closed`로 마감을 판단한다.
- [x] 투표 만들기는 마감 시각을 선택 입력으로 받는다. 지금보다 이른 시각이나 형식이 틀린 값은 이유와 함께 거절된다.
- [x] 테스트가 통과한다.
  - 마감 시각을 넣어 만든 투표는 그 시각을 가진 진행 중 투표다.
  - 지난 시각은 거절된다.
  - 마감 시각이 지난 투표는 마감이다. 표를 받지 않고, 누구나 결과를 보며, 목록에서 진행 중 투표 뒤에 온다.
  - 마감 시각 전에 운영자가 마감할 수 있다.
  - 마감 시각이 없는 투표는 그대로 진행 중이다.
- [x] 운영자 폼에 날짜·시간 입력이 있다. 운영자 기기의 현지 시각으로 입력받아 UTC로 저장한다. 검증에 실패해도 입력값이 유지된다.
- [x] 투표 화면, 운영자 결과 화면, 목록에서 진행 중 투표의 마감 시각을 한국 시간으로 "10월 3일 18:00 마감"처럼 보여 준다.
- [x] 결과 화면을 연 채로 마감 시각이 지나면 5초 폴링이 마감을 감지해 "마감"으로 바뀐다. 양식을 연 채로 시각이 지나 표를 내면 "마감된 투표입니다."가 나온다.
- [ ] 운영 배포 전에 운영 브랜치에 `npm run db:migrate`를 실행한다(사용자 확인).

## Comments

- 2026-09-30: 구현 완료. 커밋 e4dd0cd와 리뷰 반영 커밋. 테스트 56개가 통과했다(마감 시각 7개).
- 헤드리스 Chrome(시간대 Asia/Seoul)으로 확인한 것:
  - 지난 시각은 거절되고 입력이 유지된다.
  - 현지 시각으로 입력한 값이 UTC로 저장되고, 화면에는 한국 시간으로 표시된다.
  - 결과 화면을 연 채로 마감 시각이 지나면 약 12초 안에 "마감"으로 바뀌고 요청이 멈춘다. 이때 `closed_at`은 비어 있다.
  - 마감 뒤에는 표가 들어가지 않는다.
- 리뷰 반영:
  - 스크립트가 돌기 전이나 JS 없이 제출하면 마감 시각이 조용히 버려지던 버그를 고쳤다. 이제 "다시 입력하세요"로 거절한다.
  - 서버 시간대로 ISO를 계산하던 부분을 막았다.
  - 입력 칸에 시간대 안내 문구를 넣었다.
  - 이미 마감된 투표에는 `closePoll`이 `closed_at`을 새로 찍지 않는다.
  - 마감 시각 표시를 `PollDeadline` 컴포넌트 하나로 합쳤다.
- 남은 일: 운영 브랜치에 `npm run db:migrate`를 실행한 뒤 배포한다. 순서를 바꾸면 새 코드가 없는 `is_closed` 함수를 찾아 오류가 난다.
