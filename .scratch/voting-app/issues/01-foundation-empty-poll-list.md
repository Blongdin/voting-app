# 01: 기반 구축: 빈 투표 목록을 Vercel에 배포

**What to build:** 배포된 앱의 홈에 투표 목록이 나오고, 투표가 없으면 "아직 투표가 없습니다"라는 안내가 보인다. 이 화면이 보이면 DB(Neon)부터 Vercel 배포까지 전 구간이 연결된 것이다. 이후 모든 티켓이 이 위에 쌓인다.

- DB 스키마(투표, 선택지, 표)를 스펙의 데이터 모델대로 SQL 파일 하나에 정의하고, 스크립트 명령으로 적용한다(ADR-0003, ADR-0004).
- 도메인 모듈의 첫 기능으로 **투표 목록 조회**를 만든다. 정렬(진행 중 먼저, 각 그룹 안에서 최신순)과 항목별 총 표 수를 포함한다.
- Vitest가 Neon 테스트 브랜치에 연결되어 돌고, 테스트마다 테이블을 비운다.

**Blocked by:** None (can start immediately)

**Status:** done

> 사람이 해야 하는 일: Neon 브랜치 세 개(운영, 개발, 테스트) 만들기, Vercel 프로젝트 연결, 환경변수 입력은 사용자가 대시보드에서 해야 한다. 에이전트는 필요한 값과 절차를 안내하고, 나머지를 구현한다.

- [x] 스키마가 스펙의 데이터 모델과 일치한다. (투표, 참여자) 조합 유일 제약, 선택지 소속을 확인하는 복합 외래키, 투표 삭제 시 선택지와 표가 함께 지워지는 설정, 글자 수 제약을 포함한다.
- [x] 스키마 적용 명령을 두 번 연속 실행해도 오류가 나지 않는다.
- [x] 로컬은 개발 브랜치, 테스트는 테스트 브랜치, Vercel은 운영 브랜치에 연결된다. 필요한 환경변수는 DB 연결 문자열, 운영자 비밀번호, 세션 서명 키이고, 환경변수 예시 파일에 정리되어 있다.
- [x] 테스트 명령 하나로 Vitest가 테스트 브랜치에서 돈다. 연결 문자열은 `.env.test.local`의 `DATABASE_URL`에서 읽는다(`scripts/setup.sh`가 작성함).
- [x] 운영(main) 브랜치에 스키마를 적용하고 푸시하기 전에 사용자 확인을 받는다.
- [x] 투표 목록 조회 테스트가 통과한다: 빈 목록, 진행 중 먼저 정렬, 각 그룹 안에서 최신순, 총 표 수.
- [x] 홈에 투표 목록이 나오고, 비어 있으면 한국어 안내 문구가 보인다.
- [x] Vercel 배포 URL에서 홈이 운영 브랜치 데이터로 동작한다.
