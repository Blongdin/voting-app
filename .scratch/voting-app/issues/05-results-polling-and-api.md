# 05: 결과 5초 폴링과 결과 API

**What to build:** 진행 중인 투표의 결과 화면이 새로고침 없이 5초마다 갱신된다. 참여자 화면과 운영자 화면 모두 해당한다. 이를 위해 결과 조회 API를 만들며, 이 API도 결과 공개 규칙을 그대로 따른다. 그래서 주소를 직접 호출해도 표를 내기 전에는 결과를 받을 수 없다.

**Blocked by:** 04 (참여자의 표 내기와 결과 보기)

**Status:** done

- [x] 결과 조회 Route Handler 하나가 투표 ID를 받아 도메인 모듈의 결과 조회를 그대로 따른다.
  - 권한 없음: 403
  - 없는 투표: 404
  - 성공: 200과 결과 본문. 본문 형태는 스펙의 결과 API 계약을 따른다.
- [x] 응답은 캐시하지 않는다.
- [x] 표를 내지 않은 브라우저에서 진행 중인 투표의 결과 API를 직접 호출하면 403이다. 직접 실행해서 확인한다.
- [x] 진행 중인 투표의 결과 화면이 5초마다 결과 API를 다시 호출하고 화면을 갱신한다. 다른 브라우저에서 표를 내면 5초 안에 반영된다.
- [x] 탭이 숨겨지면 폴링이 멈추고, 다시 보이면 이어서 한다.
- [x] 응답에서 투표가 마감됐다고 나오면 폴링이 멈추고 "마감됨" 상태가 표시된다.
- [x] 운영자 화면의 결과 보기에서도 같은 방식으로 폴링된다.

## Comments

- 2026-09-29: 완료. 커밋 4a82062(구현)와 리뷰 반영 커밋.
- 결과 API는 HTTP 요청으로 확인했다:
  - 쿠키 없이 진행 중인 투표는 403이고, `no-store`가 붙는다.
  - 없는 ID와 형식이 틀린 ID는 404다.
  - 표를 낸 참여자, 운영자, 마감된 투표는 200이다.
- 폴링은 헤드리스 Chrome(CDP)으로 확인했다:
  - 다른 곳에서 낸 표가 약 4~5초 안에 반영된다.
  - 탭이 숨겨진 11초 동안 요청이 0번이고, 다시 보이면 곧바로 한 번 가져온다.
  - 마감되면 배지가 "마감"으로 바뀌고 요청이 멈춘다.
  - 폴링 중에 투표가 삭제되면 "찾을 수 없는 투표" 화면이 되고 요청이 멈춘다.
- 리뷰에서 찾아 고친 것:
  - 운영자 결과 화면에서 첫 화면과 폴링 결과의 "내 표" 표시가 어긋났다. 두 곳이 같은 보는 사람(`resultsViewer`)을 쓰게 했다.
  - 403이나 404를 받아도 폴링이 멈추지 않았다.
  - 늦게 도착한 응답이 새 결과를 덮어쓸 수 있었다.
  - 서버가 새 결과를 내려줘도 화면이 따라가지 않았다. 티켓 06의 마감 버튼에 필요하다.
